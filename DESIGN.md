# DESIGN.md

The visual design system of this portfolio, written down. Two purposes:

1. **Reference** — so a new change looks like it belongs.
2. **Restore point** — if an experiment goes sideways, this file describes what
   "normal" looked like, so it can be rebuilt without digging through git.

Related docs: [`CLAUDE.md`](./CLAUDE.md) (how the codebase works),
[`README.md`](./README.md) (how to run it / add a project).

---

## 1. The look, in one paragraph

Corporate-minimalist, engineering-flavoured, in two themes. A 24px blueprint
grid runs behind everything; in dark mode two soft light sources bleed in from
the corners on top of it. Content sits on cards a step away from the ground,
with thin borders and a soft ambient shadow. **One** accent — a single blue —
carries links, actions, eyebrows and markers alike; hierarchy comes from tone,
not from a second hue. Monospace is used *only* for metadata — section numbers,
tags, tech chips, spec rows — never for body copy.
Layout is a 12-column grid: most sections split asymmetrically (4/8, 7/5, 8/4)
rather than stacking full-width. Motion is subtle: things fade up as you
scroll, nothing bounces, nothing spins.

It is **four pages**, not one scroller — a home page that previews the work,
plus a dedicated page each for About, Projects, and Skills.

## 0. Page structure

Four routes under `app/`. Nav, footer, scroll progress bar and back-to-top
button live in `app/layout.tsx`, so every route shares them and only the middle
changes.

| Route | File | Contains |
|---|---|---|
| `/` | `app/page.tsx` | Hero → About → Skills → Projects → Contact |
| `/about` | `app/about/page.tsx` | PageHeader → About → Education |
| `/projects` | `app/projects/page.tsx` | PageHeader → Projects |
| `/projects/<slug>` | `app/projects/[slug]/page.tsx` | AlbumHeader → Album (one per project **with screenshots**) |
| `/skills` | `app/skills/page.tsx` | PageHeader → Skills |

Album pages are generated by `generateStaticParams` from projects that have
both `gallery` and `galleryLabel`. A project without screenshots has no album
and its slug 404s — that's intended, not a gap to fill.

**Home previews; the sub-pages are a different layout, not just a longer one.**
`About`, `Skills` and `Projects` each take a `variant` prop:

- `variant="home"` (default) — numbered `SectionHeading`, a **truncated** list,
  a top border and `py-14`, and a `ViewAllLink` to the full page.
- `variant="page"` — no heading (the `PageHeader` above it is the heading), the
  full content, no border, `py-8`, **and its own grid** (below).

This split is deliberate: home is a summary, so it uses compact chip cards and
the bento; the sub-page has room to spread out, so it uses tiles, timelines and
uniform cards. A change to one usually needs checking in the other.

How much the home page shows is two constants, deliberately easy to find:

| Constant | File | Now |
|---|---|---|
| `HOME_PROJECTS` | `components/Projects.tsx` | 3 |
| `HOME_GROUPS` | `components/Skills.tsx` | 2 |

**Contact has no page of its own** — it's the last section of `/`, and the nav
links to `/#contact`. It is the one nav entry that is an anchor rather than a
route, and the one that never shows as active.

Section numbers `01`–`05` only mean something in the home page's sequence, so
`SectionHeading`'s `num` is optional and sub-pages omit it.

## 2. Color tokens

The palette is **Technical Precision Light**. Light is the source design; dark
is derived from the same system's `inverse-*` and `*-fixed-dim` roles, so both
themes come from one spec rather than one being an invention.

Two palettes, one set of names. `app/globals.css` defines raw `--c-*` variables
on `:root` (light) and `.dark` (dark), then maps them into Tailwind through an
**`@theme inline`** block. `inline` is load-bearing: it makes utilities compile
to `color: var(--c-accent)` instead of a baked hex, which is what lets the theme
flip at runtime. Use the utility, never the hex.

| Utility | Light | Dark | Source role | Used for |
|---|---|---|---|---|
| `bg-bg` | `#f7f9fb` | `#191c1e` | background / on-surface | Page ground |
| `bg-bg2` | `#f2f4f6` | `#202325` | surface-container-low | Reserved alternate surface |
| `bg-card` | `#ffffff` | `#2d3133` | surface-container-lowest / inverse-surface | Cards, ghost buttons, icon boxes |
| `bg-card2` | `#ffffff` | `#2d3133` | — | Top of the card gradient — **equal to `card`, so cards read flat** |
| `border-line` | `#dfe0e5` | `#43474a` | outline-variant | Every border and divider |
| `text-text` | `#191c1e` | `#eff1f3` | on-surface / inverse-on-surface | Headings, primary text |
| `text-body` | `#45464d` | `#d3d6d8` | on-surface-variant | Long-form copy, bullets |
| `text-muted` | `#5b5c63` | `#b2b4ba` | outline | Secondary text, meta lines |
| `text-accent` | `#0058be` | `#adc6ff` | secondary / secondary-fixed-dim | Links, active nav, CTAs, glow |
| `accent-soft` | `#2170e4` | `#d8e2ff` | secondary-container / secondary-fixed | Light end of the primary-button gradient |
| `text-accent2` | `#0058be` | `#adc6ff` | = accent | Eyebrows, bullets, tags, "Copied!" |
| `text-on-accent` | `#ffffff` | `#001a42` | on-secondary / on-secondary-fixed | **Anything sitting on an accent fill** |
| `bg-chip` | `#f2f4f6` | `#131b2e` | surface-container-low / primary-container | Tech chips, lang toggle, theme button |
| `brand-purple` | `#8b2fa8` | `#c05fd6` | — | The Power Apps icon only |

Non-token values that exist on purpose: the aurora blobs (`#0058be`, `#003a7d`,
`#2170e4`) and the dark-mode background washes (`#131b2e`, `#0b1c30`) — all
dark-only, all inside the blue family. Brand hexes for tech logos live in
`components/icons/brandColors.ts` and are deliberately *not* themed.

### Three rules that matter

**One accent, not two.** `accent2` is an alias of `accent` — this system has a
single blue, and separation comes from weight and tone. The tokens stay
separate so intent is still readable in the markup (and so a second hue could
return without touching every file), but **do not pick a new hue for `accent2`
expecting it to mean something.**

**Never put `text-white` on an accent fill.** In dark mode the accent is a
*light* blue, so white on it is unreadable. Use `text-on-accent`, which flips to
`#001a42` on dark. This is the single most likely way to break the dark theme.

**Light is not an inversion.** The accent is `#0058be` on light and `#adc6ff` on
dark — near-opposite lightness, because each has to clear contrast on its own
ground. `muted` is the system's `outline` deliberately darkened to `#5b5c63`;
`outline` itself (`#76777d`) only reaches ~4.1:1 on `#f7f9fb` and fails small
text. Any new color needs picking twice and checking on both grounds.

## 3. Typography

Loaded via `next/font/google` in `app/layout.tsx`, exposed as CSS vars.

| Family | Token | Where |
|---|---|---|
| Inter | `font-sans` (default) | Everything by default |
| Noto Sans Thai | `font-thai` | Swapped in when `lang === "th"` |
| JetBrains Mono | `font-mono` | Section numbers, tags, chips, spec rows **only** |

Sizes are mostly literal arbitrary values rather than the default scale,
because this was ported 1:1 from a hand-written stylesheet:

- Page title (`h1` on a sub-page) — `text-[clamp(32px,6vw,48px)]`, `font-extrabold`,
  `leading-[1.1]`, and it ends in a full stop: *About Me.* / *Selected Work.*
- Hero name — `text-[clamp(34px,6vw,54px)]`, `font-extrabold`, `leading-[1.05]`
- Hero role line — `text-[clamp(18px,2.4vw,22px)]`, `text-accent`, `font-semibold`
- Section heading (`h2`) — `text-[clamp(24px,3.4vw,32px)]`, `font-extrabold`
- Section eyebrow — `font-mono text-accent2 text-[13px] tracking-wide`, as `NN · Label`
- Mono sub-labels — `text-[12px] tracking-[0.09em] uppercase text-accent2`
- Project title (`h3`) — `text-xl` · Body — `text-[15px]` / `text-[14.5px]`
- Meta lines — `text-muted text-[13.5px]` · Global `line-height: 1.65`

Clamp everything headline-sized. Nothing here uses a fixed heading px.

## 4. Layout

- **Content column:** `max-w-[1040px] mx-auto px-6`, on every section, no exceptions.
- **Section rhythm:** `py-14 border-t border-line/50` on home; `py-8` and no
  border on sub-pages, where the `PageHeader` already separates things.
- **Grid:** 12 columns, `gap-[22px]`. Sections split asymmetrically:

| Section | Split |
|---|---|
| Hero | 7 copy / 5 spec card |
| About — home | 4 heading / 8 content card |
| About — `/about` | 8 profile card / 4 core-focus card |
| Education + Experience — `/about` | 6 / 6, equal height |
| Skills — home | 2 × 2 chip cards |
| Skills — `/skills` | 8 tiles / 4 attributes (spanning 2 rows) / 8 / 12 |
| Projects — home | bento — 8 / 4 alternating, lone trailing card 12 |
| Projects — `/projects` | equal 2-column grid, no bento |
| Contact | 6 methods / 6 availability card |

All collapse to one column below `md` (hero below `lg`).

**The two projects grids are not the same component styling.** Home is the
bento (`spanFor()`), which reads as a hierarchy — the featured item is visibly
bigger. `/projects` is a uniform two-column grid where nothing is featured,
and it's the only place the corner arrow appears: an affordance only reads as
consistent when the cards it sits on are the same size.

- **Nav:** `sticky top-0 z-50`, `h-16`, `backdrop-blur-md`, `bg-bg/75`. Brand is
  the word **Phakin**, linking home. Links are `next/link` routes; the active
  one is `text-accent`, decided by `usePathname()`.
- **Mobile nav:** links hide below `md` behind a hamburger that opens a stacked
  panel under the bar. This is not optional now that sections are routes —
  without it the sub-pages are unreachable on a phone.
- **Radii:** `rounded-[18px]` cards · `rounded-xl` buttons · `rounded-[10px]`
  icon boxes · `8px` chips · `rounded-full` pills and the back-to-top button.
- **Shadow:** one only — `shadow-card`.
- **Card surface:** `bg-gradient-to-b from-card2 to-card` + `border border-line`.
  Flat `bg-card` is for buttons and icon boxes; cards get the gradient.

### z-index ladder

| z | What |
|---|---|
| 0 | Hero aurora, spotlight glow (behind card content) |
| 10 | Card/hero content sitting above a decorative layer |
| 50 | Sticky nav |
| 55 | Back-to-top button |
| 60 | Scroll progress bar (always on top) |

## 5. Components

### Buttons (`ui/Button.tsx`)
Renders an `<a>`. Shared: `inline-flex items-center gap-2 rounded-xl px-5 py-3
font-semibold text-[15px] border transition-transform duration-200`.

- `primary` — `bg-gradient-to-br from-accent to-accent-soft`, white text,
  `hover:-translate-y-0.5`. **At most one per view.**
- `ghost` (default) — `bg-card text-text border-line`, `hover:border-accent`.

Leading glyphs are plain text, not icons: `⬇`, `📞`, `→`, `↗`, `▶`.

### Chips (`.chip`, `ui/IconChip.tsx`)
`bg-chip`, 1px line, 8px radius, 13px mono, asymmetric padding
`6px 11px 6px 8px` (the icon needs less room on the left). Brand icons come
from `react-icons/si` colored from `brandColors.ts`; the four custom icons
render in `currentColor` and get a theme token class from `IconChip`.

Internal `href`s (anything starting with `/` that isn't a download and has no
`target`) render as `next/link` so navigation stays client-side. The CV keeps
its plain `<a download>`.

### SectionHeading (`ui/SectionHeading.tsx`)
Accent mono `NN · Eyebrow`, then the `h2`. Numbers run `01`–`05`, stored with
each section's data, and belong to the **home page sequence only** — `num` is
optional and sub-pages leave it off.

### PageHeader (`ui/PageHeader.tsx`)
The top of a sub-page: a big `h1` ending in a full stop, plus a lead paragraph
capped at `62ch`. Fades in on mount (not on scroll — it's above the fold).
Copy lives in `pageHeaders` in `data/site.ts`.

### ViewAllLink (`ui/ViewAllLink.tsx`)
The one link out of a home-page preview into its full page. Mono, 13px,
`text-accent`, trailing `→`, nudges `0.5` right on hover. Labels are in
`viewAll` in `data/site.ts`.

### Sub-page patterns

Three shapes that only exist on `/about` and `/skills`:

- **Timeline** (`Education.tsx`) — a `border-l` rule with a 12px ringed dot per
  entry. The dot is `border-accent` for current, `border-line` for `past: true`.
  Add entries to `educationSection.items`; it grows on its own.
- **Tiles** (`Skills.tsx`) — a group rendered as a 2/3-column grid of bordered
  cells, brand icon at 20px instead of a chip's 15px. Used for the first group,
  where the logos are worth the space.
- **Attributes** (`Skills.tsx`) — a group rendered as headed list items with a
  `detail` line under each. Used for Strengths, whose chips carry `detail` in
  `data/skills.ts`; the other groups have none and stay as chips.

Each group can also carry a `note` — the mono `// CORE_LOGIC` stamp in the
card's bottom-right corner. Metadata, so mono, so it obeys the type rule.

### SpotlightCard (`ui/SpotlightCard.tsx`)
Tracks the cursor into `--mx` / `--my`; `.spotlight-glow` paints a 480px radial
of `--spot-glow` there, fading in over `0.35s`. Its inner wrapper is
`flex flex-col h-full` so cards in a row stretch to match.

**`/projects` only.** `CardShell` in `components/Projects.tsx` picks it for the
page variant and a plain wrapper for home — the glow was too busy on a page
that's already a summary. Both keep the hover lift and the accent border, so
the two grids still read as the same component. If you add the spotlight
somewhere new, that's a deliberate choice, not the default.

### ThemeToggle (`components/ThemeToggle.tsx`)
Sun/moon button in the nav. Reads `context/ThemeContext.tsx`, which uses
`useSyncExternalStore` over the `.dark` class on `<html>` — the class is the
source of truth, set by a blocking script in `layout.tsx` before first paint so
there is no flash. Order of preference: saved choice → OS → dark.

### Screenshots: card sample → album

Two pieces, one dataset. A project gets both as soon as it has `gallery` **and**
`galleryLabel` in `data/projects.ts`; nothing else needs wiring.

**`ProjectSlideshow.tsx`** — the sample on the card. One screen at a time,
crossfading every **5s** over **1.1s**, with a position indicator along the
bottom and a "View album →" pill on hover. The whole thing is one `next/link`
to `/projects/<slug>`, so the indicator dots are `<span>`s, not buttons — a
button inside a link is invalid and breaks keyboard use.

Auto-advance **pauses on hover and focus**, and never starts under
`prefers-reduced-motion` — it loops forever, which §6 requires guarding.

**`Album.tsx`** — the full grid on `/projects/<slug>`. Responsive
(2 / 3 / 5 columns for phone screens), each cell opening the `Lightbox`
(fade + scale, Escape or backdrop to close).

`galleryAspect` drives both: `"portrait"` for phone screens, `"landscape"`
(the default) for wide captures. Images are **never cropped** — `object-contain`
throughout, because a screenshot cropped to fit a box loses the thing it's
there to show. Set the real `width`/`height` per image (read them from the
file, don't estimate) so the lightbox doesn't letterbox. Files live under
`public/images/<slug>/`, and alt text is bilingual — screen readers are users too.

### FadeIn (`ui/FadeIn.tsx`)
The standard section entrance: `{opacity:0, y:18}` → `whileInView`,
`viewport {once:true, amount:0.12}`, `0.6s easeOut`. Wrap each section **once**.

## 6. Motion

| Piece | Behavior | Timing |
|---|---|---|
| Section reveal | fade + 18px rise, once | 0.6s `easeOut` |
| Hero entrance | stagger children, 16px rise | 0.12s stagger, 0.6s each |
| RoleRotator | typewriter through `hero.roles` | remounts on `key={lang}` |
| Hero aurora | 3 blurred blobs drifting (**dark only**) | 16s / 20s / 24s |
| Theme change | background + text cross-fade | 0.3s ease |
| Spotlight glow (**`/projects` only**) | opacity on hover | 0.35s ease |
| Card slideshow | crossfade, pauses on hover/focus | 5s hold, 1.1s fade |
| Scroll progress | `useScroll` + `useSpring`, `origin-left` | spring |
| Back-to-top | fade + scale, appears past 400px | 0.2s |
| Copy notice | fade + 3px rise, auto-hides | 0.18s in, 1.8s hold |
| Hover lift | `-translate-y-0.5` (cards `-1`) | 0.2s |

**Rules:** hover motion is a half-step lift and nothing else. Entrances are
`once: true`. `prefers-reduced-motion` kills the aurora; extend that guard to
anything new that loops forever.

## 7. Bilingual constraints on design

Language is React state, not CSS (see `CLAUDE.md` §2). Design consequences:

- **Thai runs longer than English.** Never design to a fixed width or a single
  line. The hero role line reserves `min-h-[1.6em]` for exactly this.
- Thai has taller ascenders/descenders — `line-height: 1.65` is deliberate.
  Lowering it clips Thai vowel marks.
- Any new string needs both `en` and `th` in `data/*.ts`. Check both languages
  **and both themes** before calling a layout done — that's four states.

## 8. Where things are edited

| Change | File |
|---|---|
| A color, in either theme | `app/globals.css` → `:root` and `.dark` |
| A new token name | `app/globals.css` → both palettes **and** `@theme inline` |
| Blueprint grid / background wash | `app/globals.css` → `body`, `.dark body` |
| Aurora blobs (color, size, speed) | `components/HeroBackground.tsx` + `drift-*` keyframes |
| Spotlight glow color / radius | `app/globals.css` → `.spotlight-glow`, `--spot-glow` |
| Project card cover plate | `app/globals.css` → `.pcover` |
| Bento sizing rule | `components/Projects.tsx` → `spanFor()` |
| Which project is featured | order of `data/projects.ts` — first entry gets the wide slot |
| How much the home page previews | `HOME_PROJECTS` / `HOME_GROUPS` constants |
| Any copy | `data/site.ts`, `data/skills.ts`, `data/projects.ts` |
| Sub-page titles and leads | `data/site.ts` → `pageHeaders` |
| Education timeline entries | `data/site.ts` → `educationSection.items` |
| Work history | `data/site.ts` → `experienceSection.items` |
| The /about profile chips | `data/site.ts` → `about.facts` |
| Strength descriptions, card stamps | `data/skills.ts` → `detail`, `note` |
| Nav links / brand | `data/site.ts` → `nav` |
| Home section order | `app/page.tsx` |
| What's on a sub-page | `app/about/page.tsx`, `app/projects/`, `app/skills/` |
| Nav, footer, scroll furniture | `app/layout.tsx` — shared by every route |

Tailwind utilities first, always using tokens. Drop to raw CSS in `globals.css`
only for what utilities can't express: the layered background, the aurora
keyframes, the spotlight glow, the cover plate, the gallery scrollbar.

## 9. Before shipping a design change

```bash
npx tsc --noEmit && npm run lint && npm run build
```

Then check by eye across **all four states** — light/dark × EN/TH — plus hover
on a real pointer, and at mobile width, where the nav links live behind the
hamburger. Walk **all four routes**, not just `/`: a section that changed has a
home variant *and* a page variant, and they render differently.
